# Документация Unload

Документация описывает проект с нескольких сторон: от первого локального запуска до
пользовательских сценариев, внутренних процессов и долгосрочного плана изменений.

## С чего начать

| Задача | Документ |
|---|---|
| Впервые открыть проект, собрать и запустить его | [START_HERE.md](START_HERE.md) |
| Понять, что видит пользователь и как выглядит успешный результат | [USER_GUIDE.md](USER_GUIDE.md) |
| Разобраться в компонентах, потоках данных, API и состоянии | [ARCHITECTURE.md](ARCHITECTURE.md) |
| Уточнить значение термина или различие похожих понятий | [GLOSSARY.md](GLOSSARY.md) |
| Посмотреть порядок планируемых улучшений и готовность этапов | [MAINTAINABILITY_PLAN.md](MAINTAINABILITY_PLAN.md) |

Основной [README проекта](../README.md) остаётся краткой справкой по возможностям,
конфигурации и командам. Этот раздел связывает подробные документы в одну систему.

## Ракурсы проекта

### Эксплуатация приложения

[USER_GUIDE.md](USER_GUIDE.md) описывает действия и наблюдаемые состояния: какие кнопки
нажимать, почему запуск может быть недоступен, как читать статусы, где искать историю и что
происходит после обновления страницы. Внутреннее устройство сервисов туда не переносится.

### Разработка и сопровождение

[START_HERE.md](START_HERE.md) содержит короткий маршрут от клонированного репозитория до
работающего API и Angular-приложения, карту точек входа и безопасный порядок проверки изменений.

[ARCHITECTURE.md](ARCHITECTURE.md) является источником подробностей о backend, frontend,
фоновых процессах, persistence, gateway, HTTP/SignalR-контрактах и границах ответственности.

### Единая терминология

[GLOSSARY.md](GLOSSARY.md) фиксирует значения `probe`, `preset`, `run`, `extra`, `workflow`,
`activation`, `member`, `target`, `gateway` и других терминов, которые встречаются одновременно
в коде, API, интерфейсе и документации.

### План изменений

[MAINTAINABILITY_PLAN.md](MAINTAINABILITY_PLAN.md) — рабочий план с приоритетами, критериями
готовности, выполненными пунктами и точкой продолжения. Планируемое поведение в нём не считается
текущим, пока соответствующее изменение не реализовано и не проверено.

## Граница документов

- Наблюдаемое пользователем поведение описывается в `USER_GUIDE.md`.
- Внутренние сервисы, потоки и контракты описываются в `ARCHITECTURE.md`.
- Команды первого запуска и навигация по репозиторию находятся в `START_HERE.md`.
- Определения не дублируются во всех документах, а ссылаются на `GLOSSARY.md`.
- Незавершённые идеи и будущие изменения отмечаются только как план.

При изменении поведения, архитектуры, API, конфигурации, persistence или пользовательского
сценария соответствующий документ обновляется в той же задаче.
