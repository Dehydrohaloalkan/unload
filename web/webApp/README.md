# Unload WebApp

Angular-клиент для `Unload.Api`.

## Что умеет UI

- показывает 4-этапный dashboard (`сервер`, `пресет`, `выгрузка`, `extra`) в минималистичном виде;
- синхронизирует часы через `GET /api/system/time`, чтобы UI показывал backend-время;
- отображает единые статусы этапов: красный крест / синий спин / зеленая галочка;
- открывает отдельные right-drawer панели деталей для этапов 2, 3 и 4;
- запускает `preset`, `run`, `extra`, поддерживает `admin mode` с передачей `adminOverride`;
- для этапа 3 дает выбор мемберов по группам в виде grid карточек;
- показывает историю запусков за день и ссылки на скачивание файлов результатов;
- поддерживает on-demand скачивание ZIP архива результата через system API;
- восстанавливает active run, dashboard snapshot и историю после перезагрузки страницы.

## Текущий UI подробно

### Общая компоновка

- верхняя часть: заголовок и кнопка `Admin mode`;
- центральная колонка: 4 компактные карточки этапов строго сверху вниз;
- правая выезжающая панель (drawer): детали выбранного этапа;
- при открытии drawer основная колонка сдвигается влево, чтобы карточки оставались видимыми.

### Единые статусы этапов

- **красный крестик** — этап не выполнен;
- **синий спиннер** — этап выполняется;
- **зеленая галочка** — этап выполнен;
- статус-иконки цветовые (без серых дефолтных иконок Prime).

### Этап 1 — Сервер

- показывает серверное время (`HH:mm:ss`);
- карточка с зеленой/красной рамкой по факту подключения;
- tooltip на карточке показывает состояние коннекта;
- внизу краткая информация о дневном окне;
- справа сверху время выполнения пробы и иконка статуса;
- пробы считаются успешно пройденными, если `readyForPreset=true` или `presetCompleted=true`.

### Этап 2 — Пресет

- основная кнопка `Выполнить пресет` растянута на доступную ширину;
- кнопка переливается, когда этап можно запускать;
- после выполнения кнопка остается доступной, но становится визуально тусклее;
- повторный запуск требует подтверждения;
- справа отдельная кнопка перехода в детали этапа 2;
- время выполнения отображается в едином формате `HH:mm:ss`.

### Этап 3 — Выгрузка

- основная кнопка `Запустить выгрузку` растянута на ширину;
- до первого запуска за день кнопка переливается, после запуска за день становится тусклее;
- повторный запуск требует подтверждения;
- справа кнопка перехода в детали этапа 3;
- время выполнения в формате `HH:mm:ss`.

### Этап 4 — Extra

- поведение согласовано с этапом 3 (без дополнительной "вылазящей" плашки в карточке);
- основная кнопка растянута по ширине;
- переливание до первого запуска за день, затем тусклый вид кнопки;
- повторный запуск требует подтверждения;
- справа отдельный переход в детали этапа 4;
- время выполнения в формате `HH:mm:ss`.

### Детали этапов (drawer)

- этапы 2, 3 и 4 имеют **раздельные** панели, чтобы не смешивать контекст;
- панель 2: статус пресета + история запусков пресета + файлы результата;
- панель 3:
  - выбор мемберов с группировкой;
  - `Select all` / групповое выделение / индивидуальные чекбоксы;
  - мемберы отображаются в виде grid карточек (не длинным списком);
  - блок активной выгрузки показывается только пока run действительно активен;
  - история запусков за день, раскрытие по мемберам, скачивание файлов;
- панель 4: статус extra + история запусков extra + файлы результата.

### Скачивание результатов

- можно скачать отдельные файлы результата;
- можно скачать ZIP архив всей output-папки запуска через `download-archive`;
- ZIP формируется on-demand только в момент запроса (важно для больших папок).

### Персистентность UI

- после обновления страницы восстанавливаются:
  - snapshot дашборда,
  - история запусков за день,
  - last completed timestamps,
  - active run (если есть),
  - выбранные мемберы (localStorage).

### Admin mode

- включается кнопкой в хедере через 4-значный пароль `HHmm` (локальное время клиента);
- в admin mode UI отправляет `adminOverride=true` для запусков `preset`, `run`, `extra`;
- повторное нажатие на кнопку выключает admin mode.

## Стек

- Angular 21 standalone
- PrimeNG 21
- Tailwind CSS 4
- SignalR client `@microsoft/signalr`

## Локальный запуск

1. Подними API:

```powershell
dotnet run --project .\backend\Unload.Api\Unload.Api.csproj
```

2. В отдельном терминале запусти web-клиент:

```powershell
cd .\web\webApp
npm start
```

3. Открой `http://localhost:4200`.

Dev-server использует `proxy.conf.json`, поэтому запросы к `/api` и `/hubs/status` проксируются на `http://localhost:5000` без отдельной CORS-настройки backend.

## Архитектура frontend

- `src/app/app.store.ts` — store для REST, SignalR, localStorage, dashboard snapshot и derived state.
- `src/app/app.error-store.ts` — глобальная обработка runtime-ошибок Angular.
- `src/app/components/live-clock.component.ts` — карточка этапа 1.
- `src/app/components/preset-stage.component.ts` — карточка этапа 2.
- `src/app/components/run-card.component.ts` — карточка этапа 3.
- `src/app/components/extra-card.component.ts` — карточка этапа 4.
- `src/app/components/details-preset-panel.component.ts` — drawer-детали этапа 2.
- `src/app/components/details-run-panel.component.ts` — drawer-детали этапа 3.
- `src/app/components/details-extra-panel.component.ts` — drawer-детали этапа 4.

## Контракты API

UI использует следующие endpoint'ы:

- `GET /api/catalog`
- `GET /api/members`
- `GET /api/system/time`
- `GET /api/system/output-files?path=...`
- `GET /api/system/download?path=...`
- `GET /api/system/download-archive?path=...`
- `GET /api/runs/preset/state`
- `GET /api/runs/dashboard`
- `GET /api/runs/today`
- `GET /api/runs/active`
- `GET /api/runs/{correlationId}`
- `POST /api/runs/preset`
- `POST /api/runs`
- `POST /api/runs/extra`
- `POST /api/runs/{correlationId}/stop`
- SignalR hub `/hubs/status` и события `preset_state`, `run_status`, `status`

## Ограничение текущего backend-контракта

Для `extra` нет отдельного dedicated live-state endpoint/event уровня `run_status`, поэтому live-детализация этапа 4 ограничена текущим task-контрактом и историей snapshot.
